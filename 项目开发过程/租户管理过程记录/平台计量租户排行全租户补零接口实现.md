# 平台计量租户排行「全租户补零」接口实现设计

> 日期：2026-09-23　状态：已实施（30080 验证通过）
> 关联代码基线：`kaiwu` 分支

---

## 1. 背景

BOSS 平台计量页的租户用量排行调用：

```text
GET /api/v1/metering/usage/platform?...&group_by=tenant_id
```

当前 PostgreSQL 适配器只从 `metering_usage_records` 聚合。时间范围内没有计量记录的租户不会出现在结果里，导致页面只显示有记录的租户。

需求：**接口本身在按租户聚合时返回所有租户，不按租户状态过滤；没有用量的租户返回 0。**

## 2. 方案

修改 `pkg/adapters/runtime/pg_metering_service.go` 的 `QueryPlatformUsage`：

1. 仅当 `group_by=tenant_id` 时启用补零，避免改变其他聚合语义。
2. 在同一个 `WithPlatformTx` 事务内：
   - 第一步：以连接原身份查询 `SELECT id::text FROM tenants ORDER BY id`，不加状态过滤；若请求带 `tenant_id`，只加该租户 ID 过滤。
   - 第二步：执行 `SET LOCAL ROLE ani_metering_writer`，继续用既有跨租户计量聚合 SQL。
   - 第三步：在 Go 中合并结果，为 `tenants` 中存在但没有计量聚合行的租户追加 `total_quantity=0`。
3. 不改数据库权限、不加 migration：
   - `ani_app` / `ani_metering_user` 均继承 `ani_app`，可先读 `tenants`。
   - `ani_metering_writer` 仅负责跨租户读 `metering_usage_records`，不扩大它的表权限。
4. 补零行的 `resource_type` 与 `unit`：
   - 请求指定 `resource_type` 时，直接使用该资源类型及其标准单位。
   - 请求未指定 `resource_type` 时，按计量聚合结果中出现过的资源类型补零；聚合结果为空时使用 `instance_gpu_seconds` / `gpu_second` 作为页面默认维度。

## 3. 事务与权限顺序

```text
BEGIN
  SELECT id::text FROM tenants ORDER BY id        -- 原身份；可读 tenants；无状态过滤
  SET LOCAL ROLE ani_metering_writer              -- 只跨租户读计量表
  SELECT ... FROM metering_usage_records ...      -- 既有聚合 SQL
COMMIT / ROLLBACK                                  -- SET LOCAL 自动复位
```

该顺序保证租户全集查询和计量聚合查询处于同一事务与同一权限边界内；不额外提升事务隔离级别。

## 5. 测试计划

1. `group_by=tenant_id` + `resource_type=instance_gpu_seconds`：
   - 3 个租户中只有 1 个有计量记录；
   - 返回 3 条数据，缺失租户为 0；
   - 补零行资源类型和单位正确。
2. 租户查询 SQL：
   - 使用 `tenants` 表；
   - 不包含状态过滤；
   - 按租户 ID 排序。
3. 事务顺序：
   - 先查租户全集；
   - 再 `SET LOCAL ROLE ani_metering_writer`；
   - 最后查计量聚合。
4. 请求带 `tenant_id` 时：
   - 租户全集查询只返回该租户；
   - 补零只发生在该租户范围内。
5. 非 `tenant_id` 聚合：
   - 不额外查询 `tenants`；
   - 保持既有结果语义。
